## Bug Fixes

### close user-data listing, cross-user writes and open endpoints

**Commit**: [`ad804da`](../../commit/ad804da426606c281f790c5d2d3bcb62078ec606)  
**Author**: Austin Santos  

- users: no list queries (exposed every profile, email and health data);
  credits and subscription cannot be changed by the client; new profiles
  must start on the free plan.
- recipes: users create only their own recipes; sharing moves to the
  shareRecipe function. Owners cannot reassign recipes, meal plans,
  shopping lists or templates to another account.
- userItemHistory, userProductCache: updates check the stored owner, so
  another user's entry cannot be taken over.

### document id always wins; never store an id field; fix set-default version

**Commit**: [`b4e2c30`](../../commit/b4e2c309e3244558b6888addf1953fbf5a2095be)  
**Author**: Austin Santos  

id field looked like the original (shared badges; edits/deletes could hit
the wrong document). The document id now wins and add/update strip id.
RecipeDetails' set-default called updateRecipe with the whole recipe as
the id; onUpdateRecipe already saves it.
